# Local assets

The CLI manages one `<session-id>.assets/` directory beside each saved definition. Default-cache directory names use the same encoded ID as the HTML definition. Only explicitly imported or manually placed files belong here; original source files remain separate.

CLI operations share the session storage lock. Imports and HTTP file preparation also share a cancellable asset lock, preventing readers from seeing staging files without blocking browser module loading behind the session's render lock. Imports read bounded, stable regular files and reuse atomic file publication. Inventory checks enforce supported MIME types, portable paths, case collisions, file/tree limits, and link restrictions. Removal permits oversized or unsupported regular files so an owner can repair a manually edited tree. Original import sources, markup, descriptions, and committed application data are left intact.

The directory contains publishable resources, including reviewed browser code. Running sessions serve raw bytes at `/<session-id>/_assets/<relative-path>`, with GET/HEAD, bounded reads, path and link validation, origin checks, and cancellation. SVG responses use a sandbox CSP while supporting image rendering and inline styles. Browser modules are served without server-side evaluation. Public tunnels expose these resources to viewers and other link holders independently of WebSocket roles.

The worker pins an existing asset root at startup, or when a directory first becomes available. Replacing that root requires a restart; changing files inside it requires only a normal refetch. `status` reports directory presence (`configured`), route support (`available`), and the URL prefix; availability does not validate every asset. Stopped and older workers report unavailable. Invalid or inaccessible roots report a bounded error without paths. Delivery requires the saved definition to remain present, so clearing it revokes asset reads. Session transfers, rename, cache import, and clear do not yet manage the asset directory itself.
