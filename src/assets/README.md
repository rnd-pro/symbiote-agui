# Local assets

The CLI manages one `<session-id>.assets/` directory beside each saved definition. Default-cache directory names use the same encoded ID as the HTML definition. Only explicitly imported or manually placed files belong here; original source files remain separate.

CLI operations share the session storage lock. Imports and HTTP file preparation also share a cancellable asset lock, preventing readers from seeing staging files without blocking browser module loading behind the session's render lock. Imports read bounded, stable regular files and reuse atomic file publication. Inventory checks enforce supported MIME types, portable paths, case collisions, file/tree limits, and link restrictions. Removal permits oversized or unsupported regular files so an owner can repair a manually edited tree. Original import sources, markup, descriptions, and committed application data are left intact.

The directory contains publishable resources, including reviewed browser code. Running sessions serve raw bytes at `/<session-id>/_assets/<relative-path>`, with GET/HEAD, bounded reads, path and link validation, origin checks, and cancellation. SVG responses use a sandbox CSP while supporting image rendering and inline styles. Browser modules are served without server-side evaluation. Public tunnels expose these resources to viewers and other link holders independently of WebSocket roles.

The worker pins an existing asset root at startup, or when a directory first becomes available. Replacing that root requires a restart; changing files inside it requires only a normal refetch. `status` reports directory presence (`configured`), route support (`available`), and the URL prefix; availability does not validate every asset. Stopped and older workers report unavailable. Invalid or inaccessible roots report a bounded error without paths. Delivery requires the saved definition to remain present.

Rename, copy/move, and explicit private-cache import carry the whole validated asset tree, including empty directories, independently of optional committed data and metadata. SHA-256 manifests describe paths, sizes, and digests without embedding file bytes. Session-relative URLs remain unchanged. Destinations, including asset-only directories, are reserved exclusively; imports never merge trees. Clear removes only the owned tree and resets a running worker's pinned root so it can accept new assets. Originals and other sessions remain untouched.

[Transfer recovery](../projects/transfer/README.md) uses private binary backups, directory identities, and manifest comparisons. Failed imports remove only unchanged assets they created. Invalid or changed trees require reconciliation rather than following links, overwriting edits, or silently skipping files. Default's explorer exposes owned directories through saved definitions while keeping runtime artifacts private.
