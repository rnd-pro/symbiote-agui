# Built-in session manager

The CLI launches one detached manager per resolved storage scope. Its private `.manager` registry is separate from ordinary sessions, so session bulk operations cannot stop or clear it. The worker pins the library and runtime roots in its environment.

Save-folder settings use the launch project directory retained in the private registry. The authenticated operation updates that project's `.agui.json`, then uses a short-lived Node launcher to resolve and open the new scope without changing this process's environment. Existing managers, session workers, definitions, and committed data retain their paths. Environment-selected scopes are read-only. Browser requests cannot select the configuration file or launch directory.

Connected projects use a shared private `.projects.json` under the base state directory, outside library namespaces. `projects`, `connect project`, `forget project`, `switch project`, and `open folder` are authenticated manager operations. Requests use `folder` only to connect and `projectId` to select an existing connection; snapshots include availability and the current project identity. Default is permanent. Connecting requires an existing readable directory; missing remembered folders remain listed. Initial discovery recovers valid known manager scopes, and later forgetting does not reimport them. Atomic publication and an owner-checked interprocess lock serialize updates from multiple managers.

Project switching launches or reuses the destination's scoped manager and returns its private launch URL. It does not rewrite configuration, move definitions/data, or change live workers. Only successful launches update last-used time. Forgetting removes the connection without stopping sessions or deleting files, and the current project must be left before it can be forgotten. Successful CLI folder configuration also remembers its resolved folder; history failures explicitly report when configuration was already saved.

An already open manager retains its own scope if another manager forgets that connection. Its refreshes do not restore the shared connection; explicit connection or launch can remember it again.

The workspace Projects control shows the active scope, Default, and remembered folders. Switch opens a selected scope; Manage projects opens a connection dialog with folder paths, availability, last-used times, and per-project Switch, Open folder, and Forget connection actions. Save-folder configuration remains in Settings. Project discovery is independent of session discovery, so a failed session listing does not disable navigation. Navigation consumes the destination's private launch URL and clears previous session selection. Responses from before navigation or disconnect cannot populate the new view, and reconnect never replays accepted actions.

Open folder resolves a registered project on the server and rechecks its directory before calling the host OS opener. Default creates its definition-cache directory if needed and opens that directory only. The helper uses fixed `open`, `explorer.exe`, or `xdg-open` commands with one absolute path argument and no shell. Linux requires a desktop display. Opener errors retain the folder path for manual use; success returns `folderPath` as a request acknowledgement, not proof of a visible window. Listing, connecting, and switching never invoke the opener.

Project explorer uses the authenticated `project entries` and `project preview` operations with a registered `projectId` and slash-separated relative `path`. Directory requests also accept `offset`; both accept `showHidden`. The access boundary rejects traversal, escaping symlinks, and known private runtime roots, including through aliases. Default maps readable HTML/Markdown names through the definition-cache path helper and excludes other files. Directory scans and preview reads are bounded by the explorer constants; Markdown also respects the renderer's input limit. Preview opens verify file identity before reading. Files never enter the manager's asset map.

The explorer loads its root only when selected and fetches children on expansion. Ordinary status polling preserves its tree; explicit refresh, hidden-file changes, scope changes, and reconnect reset it. Revision and preview-selection guards discard delayed replies. Source binds through `textContent`; Markdown uses document-only rendering. Independent native Itemize templates keep breadcrumbs, file entries, and project connections from sharing an item class's template.

The server serves packaged assets on a dedicated loopback origin. Browser authorization consumes the launch URL fragment and retains the credential in origin-scoped storage. Every WebSocket requires the exact origin and an initial authentication message. HTTP lifecycle requests verify the private credential and process identity. Generated pages and tunnel routes do not carry manager capabilities.

The operation dictionary restricts requests to named session functions. Session mutations are serialized; mutation request IDs retain their result for ten minutes. Worker functions still perform their existing authenticated identity checks. Browser disconnects never cancel or replay accepted operations.

The manager uses uilib layouts, controls, and shared design tokens. JSDA bundles the browser client with one Symbiote instance; Tailwind compiles the page, row, controls, and library templates at startup. Register the manager's context provider before library components so shared bindings connect to the populated context. The top-level app shell separates a collapsible workspace sidebar from the scrollable session viewport, which contains the header, session views, and footer. One filter publishes matching IDs to card and table tabs; card and table selection reveal direct controls in the end sidebar. Session cards accept incoming `selected` state and publish a one-ID array through `pub-to`, sharing the table selection. Links and disclosures remain independent. Cards use Itemize. Folder settings and descriptions use library dialogs. Descriptions render through `agui-markdown` with custom-element extensions disabled, keeping user-authored documents separate from manager controls. Only the packaged Markdown runtime and fallback sanitizer assets are served on demand; the manager retains its strict content security policy. State refreshes on connection and while visible, retaining filter, sort, page, and selection state. Ordinary refreshes avoid public-network tunnel probes; explicit checks retain health only for the matching public URL.

The shared theme toggle selects light/dark. The initial theme follows the OS when no preference is saved. Preferences use origin-scoped browser storage and synchronize across tabs. Restart the manager after template or style changes to rebuild its assets.
