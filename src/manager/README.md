# Built-in session manager

The CLI launches one detached manager for the local state directory, shared by Default and every connected folder. Its private `.manager` registry is separate from ordinary sessions, so session bulk operations cannot stop or clear it. Launching from another folder reuses the process and opens that folder in the same app. Startup consolidates existing folder managers through authenticated shutdown while retaining AGUI workers.

Default save-folder settings use the launch directory retained in the private registry. The authenticated operation updates its `.agui.json` and selects the resulting folder in the same manager. Existing session workers, definitions, and committed data retain their paths. An environment override keeps this setting read-only. Browser requests cannot select the configuration file or launch directory.

Connected projects use a shared private `.projects.json` under the base state directory, outside library namespaces. `projects`, `choose project`, `connect project`, `forget project`, `switch project`, and `open folder` are authenticated manager operations. Requests use `folder` to connect, `projectId` to target a connection or explorer, and `scopeProjectId` for the folder whose sessions are being managed. Snapshots include availability and the current folder identity. `choose project` accepts no target: a fixed host-native picker supplies the path to the same connection validation, or returns `cancelled` without connecting. Picker processes run without shell interpolation, with bounded output and a 90-second timeout; failures retain manual path entry. Default is permanent. Connecting requires an existing readable directory; missing remembered folders remain listed. Initial discovery recovers valid known manager scopes, and later forgetting does not reimport them. Atomic publication and an owner-checked interprocess lock serialize registry updates from the CLI and manager.

Project switching validates the selected folder and updates its last-used time. The page changes its selected folder and refreshes sessions and the explorer without a document reload, new process, or new manager origin. It does not rewrite configuration, move definitions/data, or change live workers. Forgetting removes the connection without stopping sessions or deleting files, and the current project must be left before it can be forgotten. Successful CLI folder configuration also remembers its resolved folder; history failures explicitly report when configuration was already saved.

An already open tab retains its selected folder if another tab forgets that connection. Its refreshes do not restore the shared connection; explicit connection or launch can remember it again.

The workspace Projects control shows the active scope, Default, and remembered folders. Switch opens a selected scope; Manage projects opens a connection dialog with folder paths, availability, last-used times, and per-project Switch, Open folder, and Forget connection actions. Save-folder configuration remains in Settings. Project discovery is independent of session discovery, so a failed session listing does not disable navigation. Folder selection is retained in the URL and tab storage, and clears the previous session selection. Tabs choose folders independently. Responses from before a folder switch or disconnect cannot populate the new view, and reconnect never replays accepted actions.

Open folder resolves a registered project on the server and rechecks its directory before calling the host OS opener. Default creates its definition-cache directory if needed and opens that directory only. The helper uses fixed `open`, `explorer.exe`, or `xdg-open` commands with one absolute path argument and no shell. Linux requires a desktop display. Opener errors retain the folder path for manual use; success returns `folderPath` as a request acknowledgement, not proof of a visible window. Listing, connecting, and switching never invoke the opener.

Project explorer uses the authenticated `project entries` and `project preview` operations with a registered `projectId` and slash-separated relative `path`. Directory requests also accept `offset`; both accept `showHidden`. The access boundary rejects traversal, escaping symlinks, and known private runtime roots, including through aliases. Default maps readable HTML/Markdown names through the definition-cache path helper and excludes other files. Directory scans and preview reads are bounded by the explorer constants; Markdown also respects the renderer's input limit. Preview opens verify file identity before reading. Files never enter the manager's asset map.

The explorer loads its root only when selected and fetches children on expansion. Ordinary status polling preserves its tree; explicit refresh, hidden-file changes, scope changes, and reconnect reset it. Revision and preview-selection guards discard delayed replies. Source binds through `textContent`; code highlighting reuses the lazy JSDA Markdown runtime and sanitized code tokens with the source preview's size limit, preserving original line endings and plain source if loading fails. Markdown uses document-only rendering. Independent native Itemize templates keep breadcrumbs, file entries, and project connections from sharing an item class's template.

The server serves packaged assets on a dedicated loopback origin. Browser authorization consumes the launch URL fragment and retains the credential in origin-scoped storage. Every WebSocket requires the exact origin and an initial authentication message. HTTP lifecycle requests verify the private credential and process identity. Generated pages and tunnel routes do not carry manager capabilities.

The operation dictionary restricts requests to named session functions. Each request resolves its folder from the connected-project registry. AsyncLocalStorage supplies that folder to existing storage helpers without changing process environment; folder identity is the only project-specific input. Session locks, request history, and tunnel checks are keyed by storage root and session ID, so identical IDs in different folders stay independent. Mutation request IDs retain their result for ten minutes. Worker functions still perform their existing authenticated identity checks. Browser disconnects never cancel or replay accepted operations.

Global connection operations are independent of the tab's selected folder. Discovery scans running worker records in Default and every private library namespace, with four concurrent authenticated worker requests. It returns project identity and live clients through the worker's connection endpoint; older workers fall back to existing page discovery and retain an inspection-only notice. Per-worker and scope errors stay visible. Control credentials never enter browser results.

Connection mutations derive their worker root from a validated project ID and check the requested worker instance before acting. Their locks share the same root/session keys as ordinary lifecycle operations. Disconnect targets one page ID and closes it with the reserved transport close code, which stops browser reconnects while preserving the page. Tunnel stop closes only the connector. Public opening verifies reachability, renews at most once, verifies again, and returns a role-free URL or explicit viewer URL. Connector `readyAt` separates a fresh hostname's readiness window from an older inactive tunnel. Readiness polling shares the tunnel module's bounded helper; it retains the same URL and clears recovered probe errors. Public opening rereads worker status before renewal to avoid replacing another caller's new tunnel. The browser reserves a tab during the click to preserve user activation and navigates only after verification; blocked popups expose a verified-link fallback. Public/renewal RPC timeouts cover connector startup plus readiness polling. Failed and uncertain mutations are never replayed, and the manager refreshes its URLs after failed opening as well as success.

Selected-session controls provide Copy to project and Move to project. The transfer dialog keeps private metadata visible and makes data/metadata inclusion explicit. Destinations remain stopped; opening their project is a separate in-app folder selection. Transfers loads durable history independently of session discovery and exposes recovery after reconnect or manager restart. Incomplete transfers gate conflicting storage operations until reviewed. See the [transfer contract](../projects/transfer/README.md) for publication, locking, and recovery behavior.

The manager uses uilib layouts, controls, and shared design tokens. JSDA bundles the browser client with one Symbiote instance; Tailwind compiles the page, row, controls, and library templates at startup. Register the manager's context provider before library components so shared bindings connect to the populated context. The top-level app shell separates a collapsible workspace sidebar from the scrollable session viewport, which contains the header, session views, and footer. One filter publishes matching IDs to card and table tabs; card and table selection reveal direct controls in the end sidebar. Session cards accept incoming `selected` state and publish a one-ID array through `pub-to`, sharing the table selection. Links and disclosures remain independent. Cards use Itemize. Folder settings and descriptions use library dialogs. Descriptions render through `agui-markdown` with custom-element extensions disabled, keeping user-authored documents separate from manager controls. Only the packaged Markdown runtime and fallback sanitizer assets are served on demand; the manager retains its strict content security policy. State refreshes on connection and while visible, retaining filter, sort, page, and selection state. Ordinary refreshes avoid public-network tunnel probes; explicit checks retain health only for the matching public URL.

The shared theme toggle selects light/dark. The initial theme follows the OS when no preference is saved. Preferences use origin-scoped browser storage and synchronize across tabs. Restart the manager after template or style changes to rebuild its assets.
