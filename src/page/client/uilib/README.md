# UI library

Group components by purpose: `layouts/` for dashboard, panel, header, and toolbar; `controls/` for field, select, toggle, and theme toggle; `feedback/` for state presentation; `content/` for icons and other display primitives; `widgets/` for data-driven views. Keep each component's logic and optional template in its own folder inside its category. Shared base classes, control markup fragments, and common constants belong in `shared/`.

Import every component from `index.js` and register it before the page connects. JSDA bundles this entry into the normal page client, with one Symbiote instance and no per-session imports.

Mark code-entry fields with `data-code` on `agui-field type="textarea"` or a native `textarea` to use the shared monospace font for the editable content.

Use `agui-preloader` for indeterminate loading, with caller-provided `label` or standard accessible-name attributes. Native `hidden` bindings control visibility; text color and size utilities customize appearance. It uses native progress semantics and slows its animation for reduced motion. Loading states and the data toolbar reuse it. The gallery's Bindings tab includes standalone and compact examples; the skill documents its bindings and CSS properties.

Use independent `agui-filter` for typed search/AND filtering and `agui-table` for stable sorting, ID-based selection, and local pagination. The filter publishes matching IDs through `results-to`; bind those to the table's `filteredIds` while retaining the full source rows. User-edit targets publish only edits; computed results also react to incoming data without actions. Table selection reuses `agui-field`; its `indeterminate` property represents a checkbox's mixed indicator independently of its boolean `value`. Widgets share `agui-state` for loading, empty, and error feedback. See the [filter contract](./widgets/filter/README.md) and [table contract](./widgets/table/README.md) for configuration, caller-owned copy, bounded tools, and snapshot constraints. The skill supplies the HTML-only composition example.

Use `agui-kanban` to edit record statuses through native card dragging, keyboard moves, and scoped tools. It publishes records through `pub-to`, keeps unsupported statuses visible, and shares provider records with tables without handlers. Moves remain drafts until the common data toolbar saves declared `persist` keys. See the [Kanban contract](./widgets/kanban/README.md).

Use `agui-chart` for prepared line/bar/donut data, SVG output, ID-based selection, and a keyboard-accessible data table. Its ECharts adapter loads separately when the custom element initializes; the default bundle registers only lightweight chart code. The session server serves the exact packaged runtime path through JSDA. Shared viewers use snapshots without that runtime. See the [chart contract](./widgets/chart/README.md).

Use `agui-map` for prepared coordinates, shared ID selection, and explicit viewport publication. Leaflet, CSS, and local assets load on initialization. Configure raster tiles and attribution; the coordinate table provides keyboard access. Viewer snapshots preserve the user's viewport without a map runtime. See the [map contract](./widgets/map/README.md).

Use `agui-markdown` for provider-bound or URL-loaded documents. Its separate runtime calls JSDA's `md2html` for HTML, highlighting, and wrapper fallbacks, with sanitization before registered components enhance the document. Native/fallback sanitization, cancellation, source limits, and inert viewers share the [Markdown contract](./widgets/markdown/README.md).

Keep different-height blocks in separate rows or vertical groups, counting labels, hints, errors, and nested controls. Do not mix them in one toolbar or align them with spacers. Filter fields stack independently; table summaries and pagination occupy separate rows.

Use `agui-tabs` with direct authored `agui-tab` panels. Each panel supplies a unique string `value`, `label`, and optional `disabled` state through attributes or native bindings; the group supports `value`, `label`, `orientation`, `disabled`, and `readonly`. Pair incoming value with `pub-to` for explicit publication. Missing/unavailable selections fall back locally to the first enabled panel without writing shared state. The group uses the native slot processor for panels and keyed Itemize for internal `agui-tab-button` controls. Panels keep their DOM and subscriptions while hidden; mounted components can use native ResizeObserver for size changes on reveal. Do not emit a synthetic global resize or rebuild panel contents when switching.

Tab activation is manual, with roving focus, directional arrows, Home/End, Enter/Space, and independent nested groups. Group tools expose `set_value`/`read_value`; each enabled button exposes `select`. Native component descriptions identify the group ID and tab value for discovery. The panel observer tracks direct additions/removals only; panel state subscriptions notify their owning group. Group teardown disconnects that observer and keyboard listeners. The skill contains the authoring example and keyboard contract.

Use `agui-dialog` for authored modal contents. Boolean `value` synchronizes the internal native `<dialog>`; `open` supplies an initial attribute default. Supply `label` and `close-label`, plus optional `open-label` for a built-in opener; native property bindings use `label`, `closeLabel`, and `openLabel`. The native slot processor preserves mounted children and their bindings. Native focus management, Escape, the close control, and `method="dialog"` forms retain normal browser behavior. Closing changes presentation only, without saving, cancelling, or resetting fields. The dialog does not impose an edit policy on child controls.

The opener, close control, and scoped `open`/`close` tools share boolean publication through `pub-to`; `read_value` reports effective visibility. Incoming assignments and no-ops do not publish. Native close events publish only an actual dismissal, ignoring queued events after incoming closure or reopening. Teardown removes the listener and closes the surface. Keep dialog visibility transient and compose explicit persistence actions separately.

Use plain native `[popover]` elements with the `agui-popover` class and `popovertarget` buttons for non-modal contextual content; no popup component or popup-specific tools are added. Shared styling positions them near native invokers where CSS anchor positioning is available, otherwise using native centered positioning. Without native Popover support, content remains in the document. Viewer snapshots replace active native overlays with inert presentation surfaces, hoisted beyond clipping ancestors; popover toggle events schedule snapshots. Viewers never call modal or popover APIs. Dialog surfaces adapt to viewer dimensions; popup placement is clamped to the viewer viewport.

Use `agui-app` for a viewport-height shell: a direct header, start/end `agui-sidebar` elements around one `agui-viewport`, an optional `slot="footer"` region, and the data toolbar last as a direct child. Existing dashboards compose inside the viewport. Sidebar bodies and the viewport scroll independently; narrow screens stack sidebars. Customize `--agui-app-height` and `--agui-sidebar-width` without replacing the layout. Floating headers report focus spacing to their containing viewport, or the existing dashboard when outside a viewport.

Sidebar `value` is boolean expanded state, paired with `pub-to` for explicit publication. Without an explicit value, it defaults to collapsed below `64rem` and expanded from `64rem`, following breakpoint changes without publishing edits. The `collapsed` attribute keeps that default closed at every size. Bound values and explicit user/tool toggles override the responsive default and survive resizing. The media listener is removed on destruction. Supply `label`, `expand-label`, and `collapse-label`, or their native property bindings. Its toggle and `set_value`/`toggle` tools share one guarded edit path; `read_value` returns effective visibility. Incoming assignments and no-op requests do not publish. Disabled/read-only applies to toggling; authored fields retain their own policies. Closed panels hide, rather than destroy, their children. The sidebar uses Symbiote's native `slotProcessor` for its default content slot, before normal template processors; no custom projection or binding processor is needed.

Use `agui-icon` with a `name` attribute or native `$.name`/`state` binding. Its Material Symbols font subset is bundled locally, with no runtime font requests. Decorative icons need no text; informative icons take caller-provided accessible names. Keep the supported names and font subset synchronized using the [icon maintenance instructions](./content/icon/README.md).

Place one `agui-data-toolbar` last in the dashboard, or directly in `agui-app` when using the shell, with `bind="state: AGUI_TEXT/dataToolbar"` for page-supplied common copy, or bind an application-owned `{ texts: { ... } }` state object. It renders a floating status button and reuses native `popover`/`popovertarget` controls with shared popup styling. It defaults to all accepted `persist` declarations; optional `provider` and space-separated `keys` attributes select a subset. Set `form="FORM_ID"` when outside the form to validate it on Save. It shares a committed baseline across Save, Cancel, Import, and Export, and uses native subscriptions to track drafts. Save requires a real user event, awaits local cache publication, then delivers a bounded reference through feedback. New edits remain dirty. The reserved native `AGUI_SESSION` context supplies each page's own `role`, `connected`, and `userConnected`; viewers get their own status popup with data actions disabled outside the inert mirror, never the user's copied role label.

The popup also provides Description and Metadata buttons. Each opens a read-only `agui-dialog` and fetches the current saved files over the existing WebSocket. Descriptions use `agui-markdown` with component extensions disabled; metadata is formatted JSON rendered as text. Neither view saves data or sends feedback. These requests are unavailable to viewers and while disconnected. Supply the labels, loading/error messages, and `description.*` renderer copy through the toolbar's `texts` dictionary; the standard page copy includes them.

The component exposes scoped native tools `read_submission_status`, `read_saved_data`, and `acknowledge_submission`. Discover their actual names through the regular tools API. Saved reads require an exact retained worker receipt and matching baseline/data revision; path and pagination bound results to 8 KiB. External acknowledgements match commit ID, worker instance, markup revision, and data revision, and never reset dirty state. The same acknowledgement object can arrive through `bind="$.externalResult: APP/result"`. Missing/expired receipts and superseded data require reconciliation; this is not a durable submission history.

Internal `JsonTransfer` accepts one native file input, a getter for selected `persist` targets, a `report` callback for native component state, a caller-owned `texts` dictionary, and an optional JSON-file/manual export target from data-flow metadata. Its `pickImport()`, `importFile(file)`, `exportFile()`, and `dispose()` methods handle browser files without a worker or feedback handler. The toolbar selects a suitable manual export target from worker data-flow metadata. Metadata is loaded on startup and refreshed by Save; it does not authorize writes or reconfigure persistence bindings.

Portable files contain `{ "version": 1, "changes": [{ "provider": "APP", "values": { "records": [] } }] }`. Import requires exactly the selected providers/keys and plain bounded JSON, replaces those draft values through native contexts, and retains unrelated fields. It does not merge records, save a baseline, or send feedback. Export includes unsaved edits and reports download initiation only. Both use a 1 MiB limit. Results carry the selected bindings and an actual file-label endpoint for the toolbar's data-flow state; `initialSource` and private discovery metadata are not rewritten. Callers select an appropriate manual/JSON export destination; no local filesystem path is assumed.

Place the page-wide `agui-header` immediately before `agui-dashboard` under the same application provider. Its content uses the dashboard's maximum width and responsive gutters. A floating header reports its height to the following dashboard for focus scroll spacing.

Use `agui-popover` for floating surfaces with the shared translucent background and backdrop blur. Headers, select pickers, and data toolbars use it by default; message balloons keep a solid background.

Use `agui-message` for transient notifications. Supply `message`, `tone="info|success|warning|error"`, `timeout` in milliseconds (default 5000), and `close-label`, or bind `message`, `tone`, `timeout`, and `closeLabel` through native component state. Tones use the accent, success, warning, and danger theme colors with matching icons and foregrounds. Errors have assertive alert semantics; other tones use polite status announcements. The existing `alert` tone remains supported. A changed nonempty message opens automatically; clearing it dismisses it. Notifications stack above the floating data button, animate, expire, and dismiss independently. The data toolbar shows separate outcomes for local saves, delivery, external writes, transfers, and problems, including mixed results. Its popup retains those separate statuses and suppresses duplicate toasts while open; unchanged successes are not replayed on later failures. Text stays outside the shared message component.

Keep native rendering defaults in the shared base. Layouts process authored children through `processInnerHtml` or the sidebar's native slot processor; controls and feedback components render their own templates.

Keep all user-facing copy outside uilib and pass it through host attributes or native bindings, including accessible names, statuses, errors, and fallback messages. Missing text renders empty. Theme toggles are round native buttons with a next-action sun/moon icon and boolean `aria-pressed` for dark mode. They accept `light-label`/`dark-label` attributes or `lightLabel`/`darkLabel` property bindings for the tooltip; plain `label` is the fallback. Supply a stable `aria-label` or `aria-labelledby`; action text is the fallback accessible name. Text stays hidden unless `show-label` or boolean `showLabel` is enabled, which uses a regular text button. The shared control base supplies boolean tools, guards, and `pub-to`. Required markers use `required-mark` or `requiredMark`. Data toolbar `texts` is a string dictionary; its keys and standard page copy live in `../page-text.js`, with no component defaults or per-component JSON parsing.

Use host attributes for primitive defaults, native `bind="$.label: APP/nameLabel"` assignments for dynamic state properties, and `bind="state: APP/componentState"` for objects. Components own local state by default. Share application data through one common provider when needed; do not add a provider or JSON parser for every field. Use explicit native bindings to pass shared application data into local component properties; `ctx` does not change their storage scope.

Declare state in `init$` and use native `$`, `add$()`, and `sub()` directly. In `initCallback()`, native `defineAccessor()` connects the `state` binding to `add$(value, true)` and replays values assigned before initialization. Do not add scope resolvers, subscription wrappers, property proxies, or separate default models. Native `sub()` owns subscription cleanup; the existing context provider owns shared application state and its replacement lifecycle.

Controls own their native inputs in their templates. Configure them through host attributes and native bindings, without light DOM slots or a slot processor. Bound local properties take precedence over attribute defaults. Property bindings are incoming assignments; user edits update local control state and emit events. Add `pub-to="APP/name"` to explicitly publish changed values through the native `$` proxy to an existing context property. This is shared by fields, textareas, selects, checkboxes, radios, and toggles, including tool-driven edits. Pair it with `bind="$.value: APP/name"` for synchronization in both directions without handlers. Initialization and incoming assignments do not publish; disabled/read-only controls remain protected. The target attribute is read on each edit, so normal attribute bindings can change or remove it.

`Toggle` extends the common `Control` base for boolean values and a shared switch template. Specializations inherit its template, attributes, tools, and native input handling. `ThemeToggle` extends `Toggle` and explicitly reads and writes native shared `*theme`. Set its `ctx` to the application context; its native subscription applies that context's `theme` to `document.body.dataset.theme`. The document body owns the page background and color scheme; dashboards inherit them. No dashboard theme binding or session script is needed. It follows the system preference until an explicit light/dark theme is selected. Native subscriptions track shared changes, and the media listener is removed on destruction.

Keep templates beside their component logic and collect them in `templates.js`. Tag HTML template literals with `html` imported from `@symbiotejs/symbiote/core/html.js`; JSDA's template minifier processes tagged literals, while `/* html */` comments alone do not enable minification. This standalone helper keeps the aggregate safe to import on the server, which includes template classes in Tailwind compilation. Keep component-specific styles in colocated `styles.js` files and assign them through native `rootStyles`. Use the `css` helper with browser-valid CSS in the `components` layer; `@apply` is not processed in adopted stylesheets. Shared tokens stay in `src/page/uilib.css`. Common native control styles live in `shared/native-controls.css` and use the Tailwind pipeline. Describe each control's own states directly, without component ancestors or `:where()` selectors. Complete utilities on session markup can override component defaults. Shared viewers receive adopted root styles as inert snapshot CSS.

Selects use a padded decorative chevron driven by native `:open`, with rotation disabled for reduced motion. Use `appearance: base-select` where supported for a web-rendered picker; the native picker is the fallback and may pause animations while open. Do not add JavaScript trackers for dropdown state.

Use the self-contained catalogue and examples in `skills/agui/SKILL.md` for authoring. The packaged `src/page/uilib-gallery.html` is the manual review fixture.

Use grayscale surfaces with color reserved for accents and alerts. Inputs are recessed, default buttons use a solid contrasting fill, and panels have a soft border and shadow. Text inputs, selects, and buttons share `--agui-control-height` for height and minimum width. Checkbox/radio inputs occupy that same height around their smaller native indicators, including without a wrapping label. Toggle labels provide the shared control height around tracks sized by `--agui-toggle-height`. Textareas retain multiline sizing. Compact density reduces spacing without shrinking control targets.
