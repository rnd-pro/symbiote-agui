# Declarative list

Use `agui-list` to render provider-bound records as cards or other authored markup, without a session script. Native keyed Itemize creates item owners; the existing RAT component renders each template. The [skill](../../../../skills/agui/SKILL.md) and gallery include HTML-only examples.

- Bind `rows`, `value`, optional `filteredIds`, and caller-owned `texts`. Every record needs a unique nonempty string ID; `id-key` defaults to `id`. Shared limits allow 5,000 records and IDs up to 128 characters.
- Provide a direct child `<template>`, or `item-template="#existing-template"` for a reusable native template. The template runs in a record's own context: use `{{name}}` or `bind="textContent: name"` for plain elements, and `^name` inside a nested component such as `agui-panel`. Record fields remain separate from the list's internal selection metadata. Use text bindings for external content; author trusted markup only.
- `selection="none|single|multiple"` defaults to none. `value` is always an ID array, including single selection. Pair `bind="$.value: APP/selectedIds"` with `pub-to="APP/selectedIds"` for two-way synchronization. Items expose `data-item-id` and `data-selected`. The existing checkbox/radio controls provide accessible selection; supply `texts.selectItem`, which is followed by the record ID.
- Clicking an item's noninteractive content or pressing Enter/Space on its focused wrapper selects it. Multiple selection toggles; single selection keeps an already selected item selected. Embedded controls, links, and selected text retain their behavior. Native controls also support keyboard interaction.
- Bind `filteredIds` to an independent `agui-filter`'s `results-to` array. `null` shows all records; `[]` shows none. Unknown IDs are ignored, matching records keep source order, and filtering preserves selection outside the result. No record editing, sorting, or pagination is imposed.
- Incoming assignments and initialization do not publish. Removed IDs are ignored in effective selection without rewriting the provider. Real edits publish a fresh ID array; selecting the same set is a no-op.
- Supply `label` for the list's accessible name, and `texts` keys `selectItem`, `empty`, `loading`, `invalidRows`, `invalidState`, and `unavailable`. `error` accepts external error text. Boolean `disabled`, `readonly`, and `loading`, or invalid configuration, block selection. Loading/errors hide items and show the existing `agui-state` with caller-owned text.
- `items-class` supplies layout utilities on the item container, for example `md:grid-cols-2`. The default is one column with a gap. Item content and its visual surface come from the supplied template; selected outlines use shared theme tokens. Review cards, focus, and narrow layouts manually.

Discover `set_selection` by owner `agui-list` and the authored ID. It accepts `ids` and returns `changed`, `selectedCount`, and `filteredCount`. Native checkbox/radio tools remain scoped to their own controls. Successful edits emit bounded `agui:action` metadata with `action: "list-change"`, `property: "value"`, and counts, without records or whole selections. Viewer snapshots render the list and its controls inertly.
